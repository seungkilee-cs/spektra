## 🐛 BUGS

### 1. WASM Memory Management - Data Getter Inefficiency (MEDIUM)
**File:** `src/wasm/rust_audio_processor.js`, lines 186-190
**Severity:** MEDIUM - Performance/memory issue

**Code:**
```javascript
get data() {
    const ret = wasm.spectrogrambatch_data(this.__wbg_ptr);
    var v1 = getArrayF32FromWasm0(ret[0], ret[1]).slice();  // Creates copy
    wasm.__wbindgen_free(ret[0], ret[1] * 4, 4);
    return v1;
}
```

**Issues:**
1. `.slice()` creates unnecessary copy of entire Float32Array
2. If getter called multiple times, creates multiple copies
3. For large spectrograms (100k+ floats), adds significant memory pressure

**Impact:** Caller doesn't know multiple accesses are expensive; can't optimize.

**Recommendations:**
```javascript
// Option 1: Cache after first access
class SpectrogramBatch {
    constructor() {
        this._data = null;  // Cache
    }
    
    get data() {
        if (this._data === null) {
            const ret = wasm.spectrogrambatch_data(this.__wbg_ptr);
            this._data = getArrayF32FromWasm0(ret[0], ret[1]).slice();
            wasm.__wbindgen_free(ret[0], ret[1] * 4, 4);
        }
        return this._data;
    }
}

// Option 2: Add documentation warning
/**
 * Get spectrogram data. Note: Creates a copy on each access.
 * Cache the result if accessing multiple times.
 * @returns {Float32Array}
 */
get data() {
    // ... same code ...
}
```

## 📋 CODE QUALITY ISSUES

### 1. ESLint Rule Too Permissive (LOW)
**File:** `eslint.config.js`, line 25
**Severity:** LOW - Style/consistency issue

**Current Rule:**
```javascript
'no-unused-vars': ['error', { varsIgnorePattern: '^[A-Z_]' }],
```

**Problem:** Allows ANY uppercase/underscore variable to be unused:
```javascript
const UNUSED_VAR = calculateSomething();  // No lint error
const unused_var = calculateSomething();  // Lint error

// Better pattern:
const _unused = calculateSomething();  // Clear intent to ignore
```

**Why It's Bad:** 
- Uppercase convention is for constants, not "intentionally unused"
- Encourages sloppy code
- Doesn't clearly indicate "intentionally unused" like underscore prefix does

**Recommendation:**
```javascript
'no-unused-vars': ['error', {
    argsIgnorePattern: '^_',      // Ignore function args starting with _
    varsIgnorePattern: '^_',      // Ignore variables starting with _
}],
```

**Example of correct usage:**
```javascript
function handleEvent(_event) {  // Event param intentionally unused
    // ... code ...
}

const _legacyVar = old_calculation();  // Intentionally kept but unused
```

### 3. Unused Dependencies in package.json (LOW)
**File:** `package.json`, lines 20-22
**Severity:** LOW - Bundle bloat, maintenance burden

**Current Dependencies:**
```json
"fft-js": "^0.0.12",        // UNUSED (replaced by Rust FFT)
"fft.js": "^4.0.4",         // UNUSED (replaced by Rust FFT)
"music-metadata": "^11.0.2",
"react": "^19.0.0",
"react-dom": "^19.0.0"
```

**Issue:** `fft-js` and `fft.js` are legacy JavaScript FFT libraries no longer used since transition to Rust/WASM.

**Impact:**
- Adds ~100KB to bundle size (minified+gzipped)
- Requires periodic security updates
- Confuses developers about which FFT is being used

**Recommendation:** Remove unused FFT packages:
```json
"dependencies": {
  "music-metadata": "^11.0.2",
  "react": "^19.0.0",
  "react-dom": "^19.0.0"
}
```

**How to verify safe to remove:**
```bash
# Check if fft-js or fft.js are imported anywhere
grep -r "fft-js\|fft\.js" src/ --include="*.js" --include="*.jsx"
# Should return 0 results
```

### 4. Missing Error Handling in WASM Initialization (LOW)
**File:** `src/wasm/rust_audio_processor.js`, lines 395-421
**Severity:** LOW - Silent failures possible

**Current Code:**
```javascript
async function __wbg_init(module_or_path) {
    if (wasm !== undefined) return wasm;

    if (typeof module_or_path === 'undefined') {
        module_or_path = new URL('rust_audio_processor_bg.wasm', import.meta.url);
    }
    const imports = __wbg_get_imports();

    if (typeof module_or_path === 'string' || ...) {
        module_or_path = fetch(module_or_path);
    }

    __wbg_init_memory(imports);

    const { instance, module } = await __wbg_load(await module_or_path, imports);
    return __wbg_finalize_init(instance, module);
}
```

**Issues:**
1. If WASM file fetch fails, error propagates without context
2. If WebAssembly.instantiate fails, no fallback
3. `__wbg_load` errors aren't wrapped with helpful context

**Recommendation:** Add try-catch with better error messages:
```javascript
async function __wbg_init(module_or_path) {
    if (wasm !== undefined) return wasm;

    try {
        if (typeof module_or_path === 'undefined') {
            module_or_path = new URL('rust_audio_processor_bg.wasm', import.meta.url);
        }
        const imports = __wbg_get_imports();

        if (typeof module_or_path === 'string' || ...) {
            module_or_path = fetch(module_or_path)
                .catch(err => {
                    throw new Error(`Failed to fetch WASM module: ${err.message}`);
                });
        }

        __wbg_init_memory(imports);

        const { instance, module } = await __wbg_load(await module_or_path, imports);
        return __wbg_finalize_init(instance, module);
    } catch (err) {
        console.error('WASM initialization failed:', err);
        throw new Error(`Audio processor initialization failed: ${err.message}`);
    }
}
```

## ⚡ PERFORMANCE ISSUES

### 1. Vite Config Missing Explicit WASM Configuration (LOW)
**File:** `vite.config.js`
**Severity:** LOW - Relies on defaults

**Current:**
```javascript
export default defineConfig({
  plugins: [react()],
  base: "/spektra/",
  // No explicit WASM configuration
});
```

**Issue:** WASM loading handled implicitly by Vite's default behavior. If Vite changes defaults, could break.

**Recommendation - Optional Enhancement:**
```javascript
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import wasm from "vite-plugin-wasm";

export default defineConfig({
  plugins: [react(), wasm()],
  base: "/spektra/",
  optimizeDeps: {
    exclude: ['rust_audio_processor'],  // Prevent bundling WASM
  },
  build: {
    rollupOptions: {
      output: {
        // Ensure WASM is copied as-is
        assetFileNames: 'assets/[name].[hash][extname]',
      },
    },
  },
});
```

**Note:** Optional; current implicit handling works fine in modern Vite.

### 2. Console Logging in Hot Path (LOW)
**File:** `rust-audio-processor/src/audio_processor.rs`, lines 47, 114, 123, 139, 158
**Severity:** LOW - Debug-time issue

**Issue:** `console_log!` macro expands to `format!()` even when logging disabled, incurring overhead.

**Current Macro:**
```rust
macro_rules! console_log {
    ($($t:tt)*) => {
        #[cfg(target_arch = "wasm32")]
        log(&format_args!($($t)*).to_string());  // ← Always allocates string
        
        #[cfg(not(target_arch = "wasm32"))]
        println!($($t)*);
    };
}
```

**Problem:** `format!()` is called regardless of whether logging is enabled.

**Recommendation - Only Log Errors:**
```rust
// Only log when actually processing fails
if audio_data.len() != self.fft_size {
    return Err(format!(
        "Audio data length {} != fft_size {}", 
        audio_data.len(), self.fft_size
    ));
}

// Not every success case:
// console_log!("Processing {} samples", audio_data.len()); // REMOVE
```

## 🔨 BUILD / CONFIG ISSUES

### 1. Missing Build Script Error Handling (MEDIUM)
**File:** `_scripts/build-wasm.sh` (referenced in package.json, not provided)
**Severity:** MEDIUM - Silently continues on build failure

**Typical issue:** Build script doesn't use `set -e`, so if wasm-pack fails, npm continues building JS anyway.

**Recommended Content:**
```bash
#!/bin/bash
set -e  # Exit on first error

# Log script execution
echo "Building WASM module..."

# Ensure wasm-pack is installed
if ! command -v wasm-pack &> /dev/null; then
    echo "ERROR: wasm-pack not found. Install with: cargo install wasm-pack"
    exit 1
fi

# Build WASM with error checking
cd rust-audio-processor
wasm-pack build --target web --release --out-dir ../src/wasm || {
    echo "ERROR: WASM build failed"
    exit 1
}
cd ..

# Verify output exists
if [ ! -f "src/wasm/rust_audio_processor_bg.wasm" ]; then
    echo "ERROR: WASM binary not created"
    exit 1
fi

echo "✅ WASM build successful"
```

### 2. Build Order Dependency Not Enforced at Vite Level (LOW)
**File:** `package.json`, line 8
**Severity:** LOW - Currently requires sequential build

**Current:**
```json
"build": "npm run build:wasm && vite build"
```

**Why sequential:**
1. `build:wasm` compiles Rust → WASM
2. Generates `src/wasm/rust_audio_processor.js`
3. `vite build` bundles everything, imports the JS bindings

**Potential issue:** If developer runs `vite build` directly, missing WASM file errors occur.

**Recommendation:** Add guard in entry point:
```javascript
// src/main.jsx
import init, { WasmSpectrogramProcessor } from './wasm/rust_audio_processor.js';

// Verify WASM is loaded before app starts
try {
    await init();
} catch (err) {
    console.error('Failed to load audio processor. Build must run "npm run build" first.');
    throw err;
}

// ... rest of React app
```

### 3. No Vite Configuration for WASM Chunk Size (LOW)
**File:** `vite.config.js`
**Severity:** LOW - WASM binary goes into main chunk

**Issue:** WASM binary bundled with JS instead of loaded separately.

**Recommendation - Optional:**
```javascript
export default defineConfig({
  plugins: [react()],
  base: "/spektra/",
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          'wasm-processor': ['./src/wasm/rust_audio_processor.js'],
        },
      },
    },
  },
});
```

**Benefit:** WASM loads separately, can be cached independently, faster initial load.
